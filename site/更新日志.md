## 2026-08-08 (v61 — 播放器根因修复：Function 改用 fetch() + 恢复 preload=metadata + 静态资源边缘缓存)

**根因（抓包实测）**：

| 测试 | 结果 |
|------|------|
| Function + Range `bytes=0-65535` 请求 | HTTP 200（非206），10 秒只传 1.5MB，超时 |
| 直接静态资源访问 | `Cache-Control: max-age=0`（**无边缘缓存**，每次回源） |
| 视频文件 moov 位置 | 24/24 faststart ✅ |

**三大问题：**
1. `env.ASSETS.fetch()` 不返回可流式 body，浏览器收数据极慢（10 秒 1.5MB）
2. `preload="none"` + `pv.load()` 每次点击从零建立连接
3. `_headers` 无视频缓存规则，每次回源

**修复：**
- `functions/api/video.js`：`env.ASSETS.fetch()` → `fetch()`（走 Pages 静态资产管线，原生支持 Range + 边缘缓存）
- `site/play.html`：`preload="none"` → `preload="metadata"`，`begin()` 去掉 pv.preload/pv.load 冗余操作
- `site/_headers`：新增 `/videos/*` 边缘缓存 24 小时规则（Function 的 fetch() 命中边缘缓存后秒返回）

**预期效果**：Function 的 fetch() 走 CDN 边缘缓存（命中后毫秒级），浏览器 preload=metadata 提前加载元数据，点击即播。

- 本地已提交

## 2026-08-08 (v60 — 播放器修复：为所有MP4添加faststart)

**根因**：之前所有"播放器优化"（preload、Range、pv.load）都没解决真正的核心问题——

**20 个视频文件的 moov 原子在文件末尾**（99-100%位置），没有 `-movflags +faststart`。浏览器必须**下完全片**才能开始播放。11MB ÷ ~200KB/s ≈ **55 秒**。

**修复**：用 `ffmpeg -c copy -movflags +faststart` 对所有视频重新打包，将 moov 原子移到文件开头。重新打包不重新编码，文件大小不变、画质无损，每个文件处理仅需秒级。

- 24/24 视频已全部修复（其中 5 个已有 faststart 无需处理，19 个已修复）
- 修复后：浏览器下载几百KB 即可开始播放，实现渐进式播放
- 本地已提交（`987eb35`）
- 待：用户本机 `git add -A && git commit -m "v60: 为所有MP4添加faststart"` → 推送 → 上线

## 2026-08-08 (v59 — 播放器修复：pv.load() 强制连接视频源)

**根因**：`preload="none"` 时浏览器未连接视频源，`begin()` 中直接 `pv.play()` 无数据可播，导致"完全无法播放"。

**修复**：`begin()` 中 `pv.preload = 'auto'` 后追加 `pv.load()` 强制重新连接视频源，再 `pv.play()`。
- 与 v55（`preload="metadata"`）效果一致：点播放后浏览器连接源、缓冲、播放
- 页面加载仍为秒开（`preload="none"` 不下载）
- 保留手机端关闭背景动画优化
- 待：用户本机 `git add -A && git commit -m "v59: 播放器 pv.load() 修复"` → 推送 → 上线
